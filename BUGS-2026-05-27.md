# Known Issues and Bugs

2026-05-27

This file tracks confirmed bugs and usability issues identified during code review.
Each entry includes the affected file(s), a description, and a suggested fix.

---

## BUG-1: `perag chunk` outputs nothing on total failure, breaking pipelines

**File:** `perag/cli.py:56-58`

**Status: Fixed in 0.1.3**

**Description:** When every file argument fails (not found or unsupported), `all_chunks`
is empty and nothing is written to stdout. The downstream `perag embed` reads EOF from
stdin and raises `JSONDecodeError: Expecting value`, producing a second spurious error
message. Because both processes start simultaneously in a shell pipe, the exit-code from
`chunk` does not prevent `embed` from running.

**Fix:** Removed the `if all_chunks:` guard so `[]` is always emitted to stdout before
the process exits with code 1. Downstream stages receive valid JSON and handle the empty
array gracefully.

## BUG-2: Ollama embedder ignores batching — one HTTP request per text

**File:** `perag/embedders/ollama.py:19-29`

**Description:** `OllamaEmbedder.embed()` loops over each text individually and issues a
separate HTTP POST per text, even when called with a batch. The CLI correctly groups
texts into batches before calling `embed()`, but the batching is undone inside the
embedder. The Ollama `/api/embed` endpoint (v0.1.28+) accepts an array via `"input"`.
The current code uses the legacy `/api/embeddings` (singular) endpoint which only
accepts one text at a time.

**Suggested fix:** Switch to `/api/embed` with `"input": texts` and return all vectors
in a single request. Fall back to the loop only if the new endpoint is unavailable.

## BUG-3: No fixture files or real-file tests for PDF and DOCX chunkers

**File:** `tests/fixtures/`, `tests/test_chunkers.py`

**Description:** `CLAUDE.md` requires *"Each chunker must have at least one real-file
test (not mocked)"*, but `tests/fixtures/` contains only `sample.md` and `sample.txt`.
`PdfChunker` and `DocxChunker` have no fixture files and therefore no real-file tests.

**Suggested fix:**
1. Add `tests/fixtures/sample.pdf` — a small multi-page PDF with extractable text.
2. Add `tests/fixtures/sample.docx` — a small Word document with several paragraphs.
3. Add tests in `tests/test_chunkers.py` for both chunkers, similar to the existing
   `test_text_chunker_produces_chunks` and `test_markdown_chunker_splits_on_headings`.

## BUG-4: `_apply_section` has an invalid type annotation

**File:** `perag/config.py:34`

**Description:** The function signature is:
```python
def _apply_section(defaults: dataclass, raw: dict, cls: type) -> object:
```
`dataclass` is a decorator/callable, not a valid type annotation. Type-checkers and IDEs
will flag or misinterpret the `defaults` parameter.

**Suggested fix:** Replace `dataclass` with `Any` (from `typing`) or a suitable
`Protocol`. The return type `object` can similarly be tightened to a type variable
bounded to the dataclass types used.

## DOC-1: Config section-level override behaviour is undocumented

**File:** `CLAUDE.md`, `README.md`, `config.example.toml`

**Description:** The current behaviour is that a local `[embedding]` section fully
replaces the global `[embedding]` section (no per-key inheritance). The existing
documentation says *"A project-local config only needs to override what differs from
the global defaults"*, which implies per-key inheritance and is misleading. The
behaviour is intentional; the documentation is not.

**Suggested fix:** Update the documentation to clearly state that a local section
replaces the entire global section of the same name. Recommend that users who want
only one or two keys to differ should copy the full section from the global config
into the local config and change only those keys.

## USABILITY-1: Spinner label misleads users for API-backed providers

**File:** `perag/cli.py:97-98`

**Description:** The spinner always shows `"Loading model {cfg.embedding.model}"` when
calling `embedder.preload()`. For Ollama and OpenAI, `preload()` is a no-op (defined as
such in `embedders/base.py`), so the label implies local model loading when no such
loading occurs.

**Suggested fix:** Only show the loading spinner when the embedder's `preload()` will
actually do work. One option: add a `needs_preload: bool` property to `Embedder`
(defaulting to `False`, overridden to `True` in `LocalEmbedder`), and wrap the spinner
call in a conditional.

## USABILITY-2: `perag init` silently overwrites the user's Claude Code skill file

**File:** `perag/cli.py:183-189`

**Description:** Every `perag init` unconditionally copies `SKILL.md` to
`~/.claude/skills/perag.md`, overwriting any customisations the user may have made.
There is no warning, no `--force` guard, and no opt-out.

**Suggested fix:** Check whether `~/.claude/skills/perag.md` already exists. If it
does, print a yellow "Already exists" notice (consistent with the treatment of
`config.toml`) and skip the copy. Add a `--reinstall-skill` flag to force the
overwrite when explicitly requested.

## USABILITY-3: `perag status --full` and `perag ls` default to non-recursive scan

**File:** `perag/cli.py:292-296`, `perag/cli.py:393-397`

**Description:** Without `--recurse`, both commands use `glob("*")` (top-level only).
For users whose documents live in subdirectories, the file counts will be misleading:
files appear as "missing" in the database while their on-disk counterparts are simply
not scanned. Most real document collections are not flat, so the default is surprising.

**Suggested fix:** Either change the default to recursive, or print a note in the
output reminding the user that sub-directories are not scanned without `--recurse`.

---

## USABILITY-4: `perag embed` produces no summary on stderr

**File:** `perag/cli.py:62-112`

**Description:** After embedding completes, no summary line is printed. `perag ingest`
prints `"Ingested N chunks into <path>"`. `perag embed` is silent once the per-batch
spinners finish, making it hard to confirm the step completed as expected.

**Suggested fix:** Print a summary to stderr after embedding, e.g.
`"Embedded N chunks (M re-embedded, K passed through)"`.

## USABILITY-5: Dead `tomllib` optional dependency marker

**Status: Fixed in 0.1.3**

**File:** `pyproject.toml:19`

**Description:**
```toml
"tomllib; python_version < '3.11'",
```
`requires-python = ">=3.11"` makes this marker always false — the package can never be
installed on Python < 3.11, so the conditional dependency is never activated. `tomllib`
is part of the stdlib from 3.11 onwards and needs no explicit dependency.

**Suggested fix:** Remove the `tomllib` line from `[project.dependencies]`.
